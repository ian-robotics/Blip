# 数据模型与业务规则

## 存储协议

存储键保持为 `blip-proto-v1`，值为整个状态对象的 JSON 字符串；本次重构未变更字段，因此原有有效进度可以继续读取。同源决定存储空间：协议、域名或端口改变都会进入不同的 localStorage 空间，从 `file://` 迁到 localhost 后也不会自动迁移旧进度。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| xp | 非负整数 | 累计经验 |
| streak | 非负整数 | 演示连续天数 |
| day | 正整数 | 演示天数，起始 5 |
| doneTotal | 非负整数 | 历史完成数，起始 11 |
| sample | 非负整数 | 下一个示例句的轮播索引 |
| badges | string[] | 已获得徽章 ID，不重复 |
| week | boolean[7] | 周一至周日是否完成过任务 |
| tasks | Task[] | 当前保留任务 |
| nextId | 正整数 | 下次创建任务的 ID，大于所有现有任务 ID |

```js
// Task：已进入 Store 的任务
{ id: 1, title: 'Finish report', time: 'Tonight', prio: 'high', done: false }

// DraftTask：解析结果，确认添加后才分配 ID
{ title: 'Buy milk', time: '', prio: 'normal' }
```

`prio` 只允许 `low`、`normal`、`high`。任务 ID 唯一。时间是显示文本，不是时间戳，没有自动到期调度。

读取失败、JSON 损坏、必需字段缺失或类型错误时，返回新的演示状态。读取本身不会覆盖坏数据；下次有效动作保存时会写入新的状态。写入失败返回 `false`，Store 保留当前会话状态。修改协议时应新增显式迁移函数和兼容测试。

## Store 接口

| 方法 | 行为 |
| --- | --- |
| `getState()` | 返回当前状态深拷贝 |
| `subscribe(listener)` | 注册 `(state, events, { saved })` 回调，返回取消订阅函数；注册时不立即通知 |
| `completeTask(id)` | 完成任务；不存在或已完成时不重复奖励 |
| `deleteTask(id)` | 删除任务，不扣回已获得 XP |
| `addTasks(drafts)` | 添加已确认草稿，分配 ID，未完成任务排在前面 |
| `advanceDay()` | 推进演示日期并结算连续天数 |
| `nextSample()` | 推进示例索引并返回当前示例句 |
| `reset()` | 恢复初始演示状态并保存 |

Store 接收来自受控 UI/解析器的草稿；它不是面向不可信网络输入的校验接口。引入外部数据入口时，应先增加草稿校验。

业务事件：`task-completed { id, xp }`、`badge { id }`、`level-up { from, to }`、`day-advanced { did, streak }`、`reset`。UI 决定事件怎样展示，业务层不展示弹窗。

## 成长规则

- XP：高优先级 30、普通 20、低优先级 10；每个任务只奖励一次。
- 等级阈值：LV1 为 0、LV2 为 60、LV3 为 140、LV4 为 250、LV5 为 400。
- 完成任务时更新累计完成数及当天周记录，并检查清空任务、完成 15 项、孵化和进化徽章。
- 一次添加至少 3 项任务获得 Chatterbox；奖励不会重复发放。
- 推进日期时，当天有完成任务则 streak 加一，否则归零。移除已完成任务，保留未完成任务；进入周一时清空周记录。streak 至少为 5 时检查 On a Roll。
- 这些规则保持原型行为：跨天由按钮触发；删除当天已完成任务会影响跨天时的完成判断。暂未建立独立的历史完成日志。
- LV5 的解锁文案包含夜空主屏，但原型没有实际背景切换逻辑，本次未扩展该功能。

## 任务解析

`parse(text)` 返回草稿数组。按标点、连接短语以及动词规则拆分英文句子，保留 `buy milk and eggs` 这类宾语连接；通过关键词提取优先级和时间。它不会验证真实日期，也不提供中文语义解析。关键词同时命中时，高优先级规则先于低优先级规则。
